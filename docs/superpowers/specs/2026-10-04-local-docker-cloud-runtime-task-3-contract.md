# Task 3 execution contract

This bounded clarification resolves the implementer’s actual producer questions. It supplements the approved design; it does not authorize Docker, real credentials, remote operations, or implementation of later tasks.

## Private profiles and ownership

- Private file schema is NOT Bootstrap. Exact JSON keys: required nonblank api_key; optional base_url and model. Present optional values must be nonblank strings; null, unknown, duplicate/case-alias keys and extra documents are rejected. base_url is an absolute http(s) URL, supports provider path prefixes, and has no userinfo, query or fragment. Credential/model strings contain no control characters.
- LoadProfile(path) returns only Bootstrap.APIKey/BaseURL/Model; NodeToken/ServerURL/DaemonID remain zero for trusted later producers. Never infer owners from file content/name/HOME/OAuth.
- Path must be explicit, absolute, regular and not a final symlink; permissions include owner-read and no group/other permissions (0400/0600 accepted). No OS UID equality requirement: container Fleet may read a host-admin-owned read-only mount. Owner validation means business UUID + namespace + administrator SQL reference binding, not filename or uid inference. Invalid/unreadable profile returns sanitized ErrProfileMissing, no key/value/path echo.
- Store.GetProfile(ctx,ownerID) returns store.Profile{ID,OwnerID pgtype.UUID; Namespace,Ref string; Version int64}. Ref is the internal explicit file path. Node.ProfileRef stores canonical profile-row UUID text, NOT a caller path. Store.GetProfileForNode(ctx,node) validates persisted node ID/owner/namespace/profile-row identity and returns that Profile. Empty/missing/mismatched reference => ErrProfileMissing. Actual profile reads are outside transactions.
- Pure strict decoder: promote existing model.decodeObject to model.DecodeStrictObject(raw []byte,dst any)(map[string]json.RawMessage,error), optionally move into model/json.go; reuse its body and rename existing config/layout callers, no duplicated parser or compatibility alias. It performs no I/O/logging. Existing config/layout regression tests remain valid.

## Administrative provisioning seam

- Store.WithProvisioningConfig(cfg model.Config) Option snapshots trusted Namespace/Image/Specs only, including a defensive copy of Specs; WithMaxNodes remains separate. Namespace must match store namespace, Image nonblank, declared specs have positive resource values. New without this option still supports reads/tokens; NEW CreateIntent fails safely when config is absent/invalid. No user request can supply image/path/resources/profile.
- Request stays Name/Spec/IdempotencyKey. New intent validates declared spec and name, snapshots cfg.Image and cfg.Specs[req.Spec], resolves the configured owner profile, and stores Node.Resources model.Spec. Persist resources as fleet_nodes.spec_config jsonb; default existing rows to 2 CPU/4GiB/256 PID/1 run. Decode/validate persisted resources on read; malformed/nonpositive data returns a safe error rather than silently substituting a ready node.
- Constructor examples/tests must pass WithProvisioningConfig with explicit fake image/spec. Service/main later inject cfg; no empty-image staging. Snapshot prevents operator config changes silently changing per-node claim capacity or resource promises. Consumers Task6 use Node.Resources.MaxRuns, Task8 uses snapshot limits, Task9 receives nonsecret FLEET_NODE_MAX_RUNS from Task8 and derives daemon max-concurrent-tasks from that positive integer (default1), not fixed1 for customized specs. These are declared later obligations, not Task3 implementation work.
- Under a common owner advisory lock, first compare existing idempotency request fingerprint (Name/Spec only); matching key replays original node/op even after quota/profile/config changes. Different payload conflicts. Only a new key then checks current declared spec/profile/quota and writes node/op atomically. Terminating/failed nodes still occupy quota until terminal tombstone; no slot release on unknown health. No filesystem/HTTP in transaction.

## Credential generation

- Add fleet_node_credentials.generation bigint NOT NULL DEFAULT1. Independent of Node.Generation/Operation.Generation: those are control-operation CAS generations and mint never advances them.
- Mint takes node-exclusive lock, validates owned persisted node, finds max credential generation across retained historical rows, revokes active predecessors and inserts new hash at max+1 in the same transaction. Initial=1; generation overflow fails. Retain revoked credential history until terminal node cleanup; terminal/revoked node cannot mint. Raw token returned only for internal bootstrap.
- Verify checks exact hash, store namespace, credential-node-owner consistency, current active credential generation, credential revocation, node revocation/terminal state and existing user. Preparing maintenance/terminating intent alone does not invalidate token: accepted runs must finish/report until explicit revocation. No positive cache here. Revoke all owned node credential rows under same lock, idempotently.

## Profile projection versions

- UpsertProfiles is per-owner atomic upsert, NOT namespace replacement. Omitted owners unchanged. Explicit owner=>empty string is a retained disabled tombstone, blocking NEW provisioning; no silent delete from omission. Active references must be explicit absolute paths; DB owner must exist, UUID cannot be zero.
- Version >=1, per-owner monotonic. Lower version or same version/different reference => ErrConflict; same version/same reference is no-op. Entire batch rolls back on conflict/invalid owner; acquire the common owner locks in canonical UUID order. Empty input is no-op. Profile row ID remains stable on updates; no head/sentinel/extra table.
- Profile configuration is provision/bootstrap routing, not token revocation. Disabling/changing it does not silently revoke existing node credentials, mutate running node snapshots or abandon accepted reports. Existing node token lifecycle is explicit RevokeNodeToken/delete; GetProfileForNode returns current configured reference for the stable profile identity or ErrProfileMissing. Operator changes take effect only at explicit safe bootstrap, never key replacement of a running process.
